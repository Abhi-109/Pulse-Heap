      How this page works — in plain English

      No frameworks, no build step, no database. A few files that a browser already knows how to run.

      Tech stack

      HTML, CSS and JavaScript

      • HTML — the skeleton: panels, the form and the drawing canvas.
      • CSS — the paint: colours, spacing, rounded cards and the smooth motion.
      • JavaScript — the brain: keeps the heap in memory and redraws the page.
      The idea

      A queue where the sickest is always first

      A min-heap is a tree-shaped queue. The most urgent patient sits at the top, so finding them is instant. Adding or removing someone only walks one root-to-leaf path, which is why it stays fast — O(log n) — even with hundreds of patients.

      Rule 1 lower triage level wins · Rule 2 same level → earlier arrival wins.

      One click, step by step

      From form to animation

      1. The form is checked and turned into a patient object.
      2. heap.insert(patient) updates the array and returns a list of steps.
      3. The page replays those steps: compare, swap, compare…
      4. Tree, array chips and waiting list all redraw together.

      Why a heap beats keeping the list sorted

      n = patients waiting. A sorted array is easy to read but expensive to change; the heap trades a tiny bit of reading work for much cheaper inserts and removals.

      Operation cost: sorted array versus min-heap
      TaskSorted arrayMin-heap
      See who is nextO(1)O(1)
      Add a patientO(n) — shift everyoneO(log n) — bubble up
      Treat the next patientO(n) — shift everyoneO(log n) — sink down
